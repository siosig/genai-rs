# Contract: upstream test inventory, markers, oracle corpus

## Inventory — `tools/codegen/upstream_tests.toml`
Generated by `tools/codegen/upstream_tests.py` (run via `check_upstream_tests.py --update`), preserving hand-edited fields.
```toml
upstream_version = "2.28.0"

[[test]]
file = "models/test_generate_content.py"      # relative to google/genai/tests
name = "test_http_options_in_generate_content"   # "Class::name" for methods in test classes
case = ""                                     # table item name for table-driven entries, else ""
status = "mapped"                             # mapped | excluded | pending
rust = "tests/models/generate_content.rs::test_http_options_in_generate_content"   # for table cases: "tests/fixtures/upstream/models/generate_content.json::<case>"
reason_code = ""                              # required iff excluded: vertex | python_only | replay_infra | live_network | pydantic_only | duplicate_of
reason = ""                                   # required iff excluded
```
Order = file path, then source order.

## Checks (`check_upstream_tests.py`, exit 1 on any failure)
1. Re-inventory the checkout (R-03); every discovered test/case has an entry and every entry still exists (else `new:`/`removed:` lines).
2. `mapped` + `rust = "<path>::<fn>"`: the Rust file contains the marker line `// upstream-test: <file>::<name>` followed within 2 lines by `#[test]`/`#[tokio::test]` and `fn <fn>`.
3. `mapped` table case: the corpus JSON contains a case with that `name`, and `tests/upstream_table` has no `#[ignore]`.
4. `excluded` has `reason_code` in the closed set and non-empty `reason`; `reason_code = "vertex"` entries must match the Vertex rule set or carry a reason text.
5. `--final`: `pending == 0`. Prints counts per status and per reason code.
6. Cross-check: the number of `mapped` entries equals the number of distinct markers + corpus cases found in the Rust tree (no orphan markers).

## Marker format in Rust
```rust
// upstream-test: models/test_generate_content.py::test_http_options_in_generate_content
#[tokio::test]
async fn test_http_options_in_generate_content() { … }
```
Ported plain tests keep the **upstream name** (rule 1; R-08). Allowed `#[expect(non_snake_case)]` is not needed (Python names are snake_case).

## Test layout rule
`google/genai/tests/<dir>/test_<stem>.py` → `tests/<dir>/<stem>.rs`, declared in `tests/<dir>/main.rs` (`mod <stem>;`). Files directly under `tests/` upstream (`conftest`, `pytest_helper`, `__init__`) are infrastructure → not ported. `tests/shared/<dir>/…` → `tests/shared_<dir>/<stem>.rs`.

## Oracle corpus runner (`tests/upstream_table/`)
- `main.rs`: discovers `tests/fixtures/upstream/**/*.json` at runtime with `std::fs::read_dir` recursion from `env!("CARGO_MANIFEST_DIR")` (no new dependency); one `#[tokio::test]` per fixture file iterating its cases and collecting failures into one assertion message naming `<source>::<case>` (rule: failure names the upstream origin).
- `dispatch.rs`: hand-written `async fn call(client: &Client, test_method: &str, params: serde_json::Value) -> Result<(), gemini_genai::errors::Error>` with one `match` arm per distinct `test_method` in the corpus; a unit test fails if any corpus file contains a `test_method` without an arm.
- Request comparison: method equal; path equal after stripping the mock server origin; query compared as sorted key/value sets; JSON body equal as `serde_json::Value`; headers not compared except `x-goog-upload-*` for upload cases.
- Canned response per case from `response_body`.

## Table items outside the corpus
Items whose `test_method` is a file-local custom function (not a dotted client path) cannot be replayed generically; they are inventoried as normal tests (class `custom`) and ported/excluded like plain tests.
